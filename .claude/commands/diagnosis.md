외모진단서 제작 워크플로. 인자: $ARGUMENTS (고객명 등, 선택)

## 분기: 진단 기준이 있는가?

`brand/diagnosis-criteria.md` 확인:

### A. 파일이 없거나 골격뿐이면 → 기준 인터뷰 (최초 1회)
선우님의 머릿속 진단 지식을 끌어내 파일로 만든다. 한 번에 다 묻지 말고 **한 주제씩** 대화:
1. "고객 사진을 볼 때 가장 먼저 보는 게 뭐예요?" (1차 판단 요소)
2. 체형 — 어떤 유형으로 나누는지, 유형별 핵심 보완법
3. 얼굴/인상 — 무엇을 보는지 (톤? 이목구비 선? 헤어 비중?)
4. 스타일 방향 결정 — 어떤 기준으로 "이 사람은 이 무드"를 정하는지
5. 자주 하는 추천 / 절대 안 하는 추천
6. 테스터 PDF가 있으면 첨부 요청 → 구조·표현 분석해 기준에 반영

→ 답변을 `brand/diagnosis-criteria.md`로 정리 (선우님 표현 그대로 보존 + 구조화).
→ "기준이 저장됐습니다. 이제 진단서를 만들 때마다 이 기준대로 작성됩니다."

### B. 기준이 있으면 → 진단서 제작
1. 고객 정보 받기 (`prompts/diagnosis/intake-form.md`의 항목): 사진(끌어다 놓기 가능), 키/체형, 고민, 선호, 예산, 상황(직업/TPO)
2. `diagnosis-writer` 에이전트에 위임 → 템플릿(`prompts/diagnosis/diagnosis-template.md`) 구조로 초안
3. 초안 + [선우님 검수 포인트] 제시 → 피드백 반영 1~2회
4. 최종본 `outputs/diagnosis/YYYY-MM-DD_고객명.md` → "이 파일을 PDF 디자인에 부어넣으시면 됩니다"

## 항상
- 고객 사진은 git에 올라가지 않는 `data/` 아래에만 보관 안내
- 진단서에서 좋았던 표현·구조는 `brand/diagnosis-criteria.md`에 누적 제안 (기준이 점점 정교해지게)
